# Instinct Messenger 🤖

> **نسخة SaaS متعددة المتاجر**: كل متجر ليه حساب وقاعدة بيانات وملفات منفصلة تمامًا، وفيه لوحة إدارة للمنصة (`/admin/`) وصفحة هبوط (`/`) ولوحة المتجر (`/app/`). التفاصيل تحت في "المنصة (SaaS)".

بوت مبيعات يرد على عملاء **ماسنجر وإنستجرام وواتساب**، يرشّح المنتجات، ياخد الأوردر ويسجّله، وكل حاجة فيه **قابلة للتحكم من لوحة تحكم عربية** — مفيش أقسام ولا حقول ولا أسعار ثابتة في الكود.

## اللي بيعمله
- **ردود ذكية بـ Claude** بلهجة مصرية مهذبة (الشخصية والتعليمات بتكتبها إنت)، ويفهم **صور العميل** (يلاقي المنتج الشبيه، يقرأ إيصال) ويبعتله **صور المنتجات**.
- **المنتجات من Google Sheet / Excel / CSV**: أي أعمدة (مقاس، لون، خامة…) بتتحول لخصائص تلقائيًا، والأقسام بتتعمل لوحدها، مع تحديث تلقائي. وتقدر تضيف/تعدّل منتجات من اللوحة.
- **تعليمات لكل قسم ولكل منتج** (مثلًا الأحذية: "اسأل عن المقاس الأوروبي") + حقول لازم البوت يسأل عنها قبل الإضافة للسلة.
- **الأوردرات**: يجمع البيانات (الحقول من إعداداتك)، يحسب الشحن **حسب المحافظة**، يعرض ملخص ويطلب تأكيد صريح، ويسجّل. الأوردر يظهر في اللوحة لحظيًا بتنبيه صوتي، ويتبعت لشيت Google (Apps Script) وتليجرام، ويتصدّر Excel/CSV. المخزون بينقص تلقائيًا.
- **أوضاع البيع والخصومات**: أوضاع قابلة للتبديل (عادي / بيع نشط / خدمة عملاء) وقواعد خصم (مثلًا 10% لو العميل هيمشي). البوت **ما يقدرش** يخترع خصم: السيرفر هو اللي بيفرض القواعد والحدود.
- **بيتعلم**: لما يتسأل حاجة ما يعرفهاش بيقول للعميل "هتأكد"، وبيوصلك السؤال. إجابتك مرة واحدة بتتحفظ في **قاعدة المعرفة** وبيستخدمها بعد كده (تلقائيًا أو بموافقتك).
- **ما يهنّكش**: طابور شغل دائم (ما بتضيعش رسائل لو السيرفر وقع)، تجميع رسائل العميل المتتابعة، إعادة محاولة، منع التكرار، مهلة وردّ اعتذار + تحويل لموظف عند الفشل، وصفحة صحة النظام.
- **تحويل لموظف**: بكلمات مفتاحية أو بقرار البوت. وأول ما ترد أنت من اللوحة أو من صندوق الصفحة البوت بيسكت المدة اللي تحددها.

## المنصة (SaaS)
| المسار | مين بيستخدمه |
|---|---|
| `/` | صفحة الهبوط العامة (الأسعار بتتقري من الباقات الحقيقية) |
| `/app/` | لوحة المتجر: مالك (كل حاجة) أو موظف (أوردرات ومحادثات وأسئلة البوت بس) |
| `/admin/` | سوبر أدمن المنصة: المتاجر، الباقات، الدفعات، إعدادات الذكاء الاصطناعي، السجلات |
| `/webhooks/meta/<slug>` | Webhook ميتا الخاص بكل متجر (التوكنات والتحقق منفصلة لكل متجر) |

- **عزل كامل:** قاعدة SQLite وملفات (`data/tenants/<id>/`) لكل متجر، والكود بيشتغل جوه سياق المتجر، فمستحيل متجر يشوف داتا متجر تاني.
- **الباقات والحدود:** منتجات، ردود ذكية شهريًا، قنوات، موظفين. تجربة 14 يوم، وبعدها الاشتراك لازم يتجدد. حد الردود الذكية بيحوّل المحادثات لصاحب المتجر بدل ما يتخطّى الحد.
- **مخفي عن العميل (بالسيرفر مش بالواجهة بس):** مفتاح Claude والموديل وحدود الأداء، القواعد الأمنية في البرومبت، أسماء الأدوات ومدخلاتها في المحادثات، السجلات وأخطاء النظام، وحالة الطابور.
- **الدخول كعميل (Impersonation):** السوبر أدمن بيدخل على أي متجر للدعم، مع شريط واضح وتسجيل في سجل التدقيق.
- **الدفع:** يدوي حاليًا (تحويل/InstaPay): العميل بيطلب الترقية، والأدمن بيسجّل الدفعة فيتمدّد الاشتراك. مفيش بوابة دفع أونلاين متوصلة.

## تشغيل سريع
```bash
npm install
SUPERADMIN_EMAIL=you@example.com SUPERADMIN_PASSWORD='ChangeMe-123' npm start   # http://localhost:3000
npm test
```
بدون المتغيرين، السيرفر بيطبع **كود إعداد** في السجل تستخدمه في `/admin/` لإنشاء أول سوبر أدمن.
بعدها: `/admin/` ← إعدادات المنصة ← مفتاح Claude، ثم سجّل متجرك من `/`.
بعدها اقرأ **[docs/SETUP.md](docs/SETUP.md)**: خطوات مفتاح Claude، الشيت، الأوردرات، وربط Meta (ماسنجر/إنستجرام/واتساب).

> محتاج Node.js 22.5+ (قاعدة البيانات SQLite مدمجة، مفيش خدمات خارجية للتشغيل المحلي).

## هيكل المشروع
```
src/
  server.js        Express + webhook Meta + تسجيل مهام الطابور
  db.js            SQLite + الإعدادات (كلها قابلة للتعديل) + بيانات أولية
  defaults.js      القيم الافتراضية (برومبت، محافظات، أوضاع، خصومات)
  importer.js      قراءة CSV/XLSX/Google Sheet + ربط الأعمدة + upsert
  catalog.js       المنتجات والأقسام والبحث العربي
  cart.js          السلة، الشحن، الخصم، ملخص الأوردر وحمايته، إنشاء الأوردر
  queue.js         طابور دائم + debounce + إعادة محاولة
  ai/              البرومبت، الأدوات، Claude، الوضع التجريبي، الـ agent
  channels/        Meta (ماسنجر/إنستجرام/واتساب) + إرسال وتقسيم الرسائل
  platform.js      قاعدة المنصة: متاجر، مستخدمين، باقات، استهلاك، دفعات
  tenancy.js       عزل المتاجر (AsyncLocalStorage) + مسارات الملفات
  visibility.js    اللي بيتخبّى عن العميل
  routes/          auth (عام) · api (المتجر) · account (حسابي/اشتراك/فريق) · admin (المنصة)
public/            / صفحة الهبوط · app/ لوحة المتجر · admin/ لوحة المنصة · shared/ التصميم
docs/              دليل الربط + سكريبت Google Apps Script
test/              اختبارات (تدفق كامل، webhooks، استيراد، حلقة Claude بسيرفر مزيّف)
```

## التصميم
الألوان والخطوط والـ radius مأخوذة من [Taste Skill](https://www.tasteskill.dev/): palette `cobalt-on-sand` وخط `Mona Sans` (+ `IBM Plex Sans Arabic` للعربي)، وواجهة محايدة بلون أكشن واحد وخطوط رفيعة بدل الظلال. صفحة الهبوط اتبنت بالـ skill نفسه ومرّت على فحوصاته؛ الـ gate خلص بـ `OPEN` (راجع "حدود" تحت).

## حدود لازم تعرفها
- **صفحة الهبوط والـ gate:** Taste Skill مبني على اتجاه LTR، فكتير من فحوصاته الهندسية (`edge-left` و`off-grid` و`container-edges`...) بتفشل على صفحة عربية RTL رغم إن الشكل سليم بصريًا. باقي الفشل: تباين الـ muted في الـ palette المرمية (6.2:1 بدل 7:1)، وقسمين خفيفين (`sparse`)، وتصادم عند عرض 320px.
- **كل متجر بياخد تطبيق Meta الخاص بيه** حاليًا (توكنات المتجر نفسه). ربط مركزي بتطبيق واحد للمنصة (Embedded Signup) تطوير لاحق.
- **قاعدة SQLite لكل متجر** مناسبة لمئات المتاجر على سيرفر واحد؛ فوق كده ننقل لـ Postgres وطابور خارجي. لازم Volume دائم على `DATA_DIR`.
- **الوضع التجريبي** (بدون مفتاح Claude) قواعد بسيطة للتجربة فقط، مش للعملاء.
- تكامل Claude اتختبر بسيرفر Anthropic مزيّف (شكل الطلبات ودورة الأدوات)، وتكامل Meta اتختبر بأحداث webhook مصطنعة. **التجربة الحقيقية محتاجة مفاتيحك** (دليل الربط).
- واتساب خارج نافذة الـ 24 ساعة (Template messages) غير مدعوم حاليًا.
- الأوردرات بتتنسخ لشيت عبر Apps Script (من غير OAuth). لو عايز كتابة مباشرة بـ Google API ده تطوير لاحق.
